タスクを完了できるようにする

  • 状態: 確定
  • 対象コミット: e6d91e36adc800fcba1af9b1d827a01906a4c3c7

要求

タスクを完了できるようにする。完了状態を表示し、選択したステータスで一覧を絞り込めるようにする。

目的

タスクの完了状況を管理し、必要なステータスのタスクを一覧で確認できるようにする。

現状

対象コミットでは、SQLiteにタスクのIDとタイトルを保存する。画面から作成・一覧表示・タイトル編集ができる。APIは一覧・作成・タイトル更新に対応する。完了状態やステータスによる絞り込みはない。

根拠: backend/src/app.ts、frontend/src/App.tsx、tests/api/tasks.test.ts、tests/e2e/tasks.spec.ts。

振る舞い

  • [SPEC-01] タスクのステータスは未完了または完了とする。利用者は未完了のタスクを完了にし、完了したタスクを未完了に戻せる。
  • [SPEC-02] 完了したタスクを一覧に表示するとき、完了であることが分かるようにする。
  • [SPEC-03] 新規タスクと機能追加前に保存された既存タスクは未完了から始まる。ステータスは保存し、画面の再読み込みと同一DBでのAPI再起動後も保持する。
  • [SPEC-04] 一覧では未完了・完了のステータスを1つ以上選択できる。選択したステータスに合致するタスクのみを表示する。
  • [SPEC-05] 画面を開いた直後は未完了のみを選択する。画面を再読み込みした後も初期選択に戻す。
  • [SPEC-06] 最後に選択されているステータスは解除できず、常に1つ以上が選択された状態を保つ。

受け入れ条件

  • [AC-01] 未完了タスクを完了にでき、完了タスクを未完了に戻せる。完了タスクを一覧に表示したとき完了と識別できる。
  • [AC-02] 機能追加前の形式で保存された既存タスクを未完了として扱い、IDとタイトルを保持する。新規タスクも未完了として作成する。
  • [AC-03] 完了と未完了の変更結果を、画面再読み込み後と同一DBを使ったAPI再起動後にも保持する。
  • [AC-04] 未完了のみ、完了のみ、両方の各選択で、選択したステータスに一致するタスクだけを一覧に表示する。ステータス変更後も現在の選択に従って表示する。
  • [AC-05] 画面を開いた直後と再読み込み後は、未完了のみを選択し、そのタスクだけを表示する。
  • [AC-06] 1つだけ選択されているステータスの解除を試みても、その選択を維持する。
  • [AC-07] 既存の作成・一覧・タイトル編集とタイトル入力の検証を維持する。保存失敗時はエラーを表示する。
  • [AC-08] 入力不正や存在しないタスクなどの不正な要求には、適切な4xxのAPIレスポンスを返す。HTTP 500は、DBへのアクセス障害などの想定外のサーバー側エラーに使用する。

課題: タスクに期限を追加する

既存のタスク管理アプリに任意の期限を追加してください。

受け入れ条件

  • タスクの作成・編集時に期限を入力または解除でき、一覧で確認できる。期限は日付だけを扱い、時刻やタイムゾーンは扱わない。
  • APIのタスク表現に dueDate を追加する。値は実在する日付を表す YYYY-MM-DD 形式の文字列か null とする。
  • 作成時に dueDate を省略した場合は null とする。更新時に省略した場合は既存の期限を維持し、null の場合は期限を解除する。不正な期限は400とする。
  • 既存のDBを開いた場合、既存タスクを保持して期限を null にする。アプリを再起動しても変更は保持される。
  • タイトルの既存の仕様と、作成・一覧・更新の既存の動作を維持する。入力・保存エラーは画面に表示する。
  • この変更に必要なAPIテストと画面E2Eテストを追加・更新する。既存の受け入れ条件を弱めない。
  • npm run typecheck、npm run lint、npm test、npm run test:e2e を実行し、結果と変更ファイルを報告する。テストの変更理由も報告する。

この課題のコードをコミットしないでください。評価用資産を探さないでください。
