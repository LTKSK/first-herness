# テストの変異による評価

評価者はStrykerJSで実装に変異を加え、既存のテストが検出できるかを調べる。元の候補とテストを変更せず、コピーしたコードと試行専用のMySQLを使う。

- 対象となる実装ファイルと必要に応じて行範囲を指定する。VitestのAPI・単体テスト、またはPlaywrightの画面テストを選べる。
- MySQLを共有するテストが干渉しないよう、変異の同時実行数は1とする。画面テストは各変異の開始前に試行専用DBを初期化する。
- 候補のコミット、変更の有無、対象、実行時刻と終了結果を記録し、変異ごとの結果をJSONとHTMLに保存する。
- 実行時の中断では子プロセスを停止し、試行専用のMySQLとボリュームを削除する。
- Strykerの終了コードとスコアだけで合否を決めない。各変異の結果と失敗理由を確認し、対象のテストによる検出、環境エラー、等価な変異を区別する。

## 確認方法

- `npm run test:mutation:smoke`: 検索語の前後の空白を除かない変異を、対応する画面テストが検出する。
- `npm run test:mutation -- frontend/src/search.ts:7-7`: 選んだ行の変異をVitestで調べる。
- 実行方法と判定上の制限は [README](../README.md) と [評価手順](../.agents/skills/agent-harness/references/evaluation.md) を参照する。
