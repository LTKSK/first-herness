# リファクタリング

既存の振る舞いを維持しながら、変更とテストを容易にする。

1. 対象の仕様、既存テスト、変更箇所、依存関係を調べる。具体的な変更を想定し、影響範囲と変更しにくい理由を整理する。影響範囲の広さだけではリファクタリングを決めない。
2. 一緒に変わる処理がまとまっているか、異なる理由で変わる責務が混在していないか、無関係な準備や過剰なmockなしに振る舞いをテストできるかを確認する。コードの見た目だけを理由に共通化しない。同じ理由で変わるルールかを確かめる。
3. lintの複雑さや行数などの警告は調査のきっかけとして扱う。数値を下げるためだけに分割・共通化せず、問題がなければ理由を記録する。
4. 変更前に関連テストを実行する。必要な振る舞いを既存テストで確認できない場合は、先に適切なテストを追加する。テストの方針がある場合はそれに従う。
5. 目的に必要な範囲だけを整理し、振る舞いの変更と区別できるようにする。関連テストと型検査・lintを実行し、結果と未確認の範囲を記録する。
6. 実施した整理、判断理由、維持した振る舞い、確認結果を報告する。仕様の変更が必要になった場合は別に扱い、必要な製品上の判断をユーザーに確認する。
